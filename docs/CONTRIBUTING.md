# Contributing to AI Showdown

AI Showdown is a Godot 4.7 parody fighting game forked from
[clintcan/3d-fighter](https://github.com/clintcan/3d-fighter). This guide gets you from a
fresh checkout to adding a fighter, tuning moves, swapping voices, building a stage or
changing the branding. Most content is **generated by scripts in `tools/`**, so the main
rule is: change the generator, re-run it, commit the output.

## 1. Project layout

| Path | What lives there |
|---|---|
| `data/characters/` | The AI Showdown roster (11 `.tres` files). **Generated** by `tools/build_showdown_roster.gd`. |
| `data/kits/` | The original 3D Fighter cast (kenji, rhea, brutus, valka, jin, mira, lian, aelia). They are the *kits*: movesets, CPU personalities and showcase routines the roster is built from. Engine tests run on these (see below). |
| `data/moves/<id>/` | One `MoveData` `.tres` per move, per fighter. **Generated** (copied from the kit, renamed, damage-scaled). |
| `scripts/` | Game code. Autoloads in `scripts/autoload/` (`game_state.gd`, `audio.gd`), fighter logic in `scripts/fighter/` (`move_data.gd`), CPU in `scripts/ai/ai_controller.gd`, UI in `scripts/ui/`, stage code in `scripts/stages/`. `scripts/character_data.gd` is the `CharacterData` resource. |
| `scenes/stages/` | Stage scenes. The three AI Showdown stages (`server_farm.tscn`, `mensa.tscn`, `senate.tscn`) inherit original ones (`rooftop`, `dojo`, `ring`). |
| `tools/` | Generators and renderers (`build_*.gd`, `render_*.gd`, `balance_sim.gd`, Python art/voice scripts). |
| `tests/sim_test.gd` | The one test suite: engine tests plus `showdown_tests()` for the roster, stages and title. |
| `assets/ui/` | `portraits/<id>.png`, `cutins/<id>.png` (+ `_alt`), `stages/<stage>.png` thumbnails, `logo.png`, `splash.png`, `wallpaper.png`, `icon.*`. |
| `assets/audio/voice/fighters/` | Per-fighter shouts (`<id>_<kind>_<n>.ogg`) and `mouth.json`. |
| `docs/` | `characters/*.md` (design notes for the original eight kits), `screenshots/`, this guide. |

**Two content sets.** The game runs on `data/characters/` and `GameState.STAGES`. The
engine tests are written against the original eight fighters and eight stages, so
`GameState.use_engine_content()` (`scripts/autoload/game_state.gd`) loads `KIT_DIR` and
`ENGINE_STAGES` instead. `showdown_tests()` at the end of `tests/sim_test.gd` switches
back with `gs.load_roster()` and `gs.stages = gs.STAGES`.

**Why kits matter.** `CharacterData.kit` (`scripts/character_data.gd`) names the kit a
fighter was built from, and `kit_id()` returns it (falling back to the fighter's own id for
the original cast). `AIController.PERSONALITIES` (`scripts/ai/ai_controller.gd`) and
`FighterShowcase.ROUTINES` (`scripts/ui/fighter_showcase.gd`) are looked up by `kit_id()`,
so a new fighter gets the CPU style and the character-select showcase of its kit with no
extra code.

## 2. Setup and running

1. Install **Godot 4.7.2** (the standard build, not .NET) and put the binary on your
   `PATH` as `godot`. Any `godot` alias or full path works in the commands below.
2. Clone the repo and import the assets once (needed before the first run and after
   adding any PNG, OGG or model):

```bash
godot --headless --path . --import
```

Run the game:

```bash
godot --path .
```

Open the editor:

```bash
godot -e --path .
```

Run the tests (exit output ends with a pass/fail summary; run before every PR):

```bash
godot --headless --path . -s res://tests/sim_test.gd
```

### Tools that render images

`render_portraits.gd`, `render_cutins.gd`, `render_stage_thumbs.gd`, `render_key_art.gd`,
`render_model_sheet.gd` and `render_screenshots.gd` need a real renderer, so they cannot use `--headless`. On a
desktop, run them normally (`godot --path . -s res://tools/<tool>.gd`). On a headless Linux
box, wrap them in Xvfb:

```bash
xvfb-run -a -s "-screen 0 1920x1080x24" godot --rendering-driver opengl3 --path . -s res://tools/<tool>.gd
```

Arguments after a bare `--` are passed to the tool (`OS.get_cmdline_user_args()`), usually
a list of ids to rebuild, e.g. `-- tesla jensen`.

## 3. Add or change a fighter

A fighter is one entry in `ROSTER` plus an outfit, a face, a portrait and a cut-in. The
ids are used in file names (`data/characters/<id>.tres`, `data/moves/<id>/`,
`assets/ui/portraits/<id>.png`, `assets/ui/cutins/<id>.png`, `assets/audio/voice/fighters/<id>_*`),
so pick a short lowercase id and never rename it later without renaming those files.

### 3.1 Pick a kit

The `kit` decides moves, frame data, animations, CPU personality and showcase.

| `kit` | Archetype | Plays like |
|---|---|---|
| `kenji` | Balanced | All-rounder: fireball, invincible uppercut. Used for the zoners (jensen, sundar). |
| `rhea` | Rushdown | Fastest walk and dash, low slide, frail. Used by tesla and algorithm. |
| `brutus` | Power | Slow heavy hitter, shrugs off knockback, ground-pound shockwave. Used by yann. |
| `valka` | Grappler | Command grabs, spins through fireballs. Used by zuckerbot and donald. |
| `jin` | Kicker | Longest reach, overhead axe kick. |
| `mira` | Brawler | Punch strings into flip kicks; Focus power-up stance. Used by ram. |
| `lian` | Counter | Reversal stance that catches strikes and throws. Used by dario. |
| `aelia` | Knight | Super armour on heavy moves. Used by geoff and xi. |

Details: `data/kits/<kit>.tres` (`archetype`, `description`, `moves`) and
`docs/characters/<kit>.md` (numbers, inputs, signature mechanic). The move **file names**
you need for the `moves` rename map are the `.tres` names in that kit's moves, e.g.
`ki_blast`, `rising_dragon`, `dragon_barrage` (kenji). Look at an existing roster entry for
the same kit as a template.

### 3.2 Edit the `ROSTER` const

In `tools/build_showdown_roster.gd`. One dictionary per fighter; order in the array is the
character-select order (`select_order`). Fields:

| Field | Meaning |
|---|---|
| `id` | `StringName`, e.g. `&"tesla"`. Also the file stem everywhere. |
| `name` | Display name (a parody spelling, never the real name). |
| `kit` | One of the kit ids above. |
| `archetype` | Short label shown on select (e.g. "Heavy Grappler"). |
| `description` | One or two lines of satire for the select screen. |
| `skin` | One of `&"light"`, `&"light_alt"`, `&"medium"`, `&"brown"`, `&"tan"`, `&"pale"`, `&"warm"` (see `SKINS`). Mirror matches use the dark skin automatically. |
| `face`, `face_rest`, `eyes`, `brows` | Optional facial structure, resting expression, iris colour and eyebrow shape; see [Face, eyes, brows and skin](#face-eyes-brows-and-skin). |
| `hair` | Array of pieces from `assets/characters/hair/` (e.g. `["Hair_SimpleParted"]`, `["Hair_Buzzed", "Eyebrows_Regular"]`); `[]` for none. |
| `hair_color`, `alt_hair_color` | `Color` for P1 and the mirror-match alternate. |
| `damage` | Multiplier on every move's damage and chip damage (1.0 = kit default). |
| `stats` | Dictionary of `CharacterData` property overrides, e.g. `{max_health = 1100, walk_speed = 1.8, weight = 1.1}`. Property names come from `scripts/character_data.gd`. |
| `moves` | Rename map: kit move file name -> new display name. A super's follow-up files share the super's name. Unlisted moves keep the kit name. |
| `projectile_color` | Optional. Recolours the fireballs of moves that have `projectile_speed > 0`. |
| `voice` | Fallback voice id (`&"kenji"`, `&"jin"` or `&"brutus"`) used for special and KO shouts when the fighter has no clips of their own. |
| `color` | Placeholder/accent colour (menus, cut-in rim light). |
| `intro`, `wins` | Arrays of quote strings. |
| `rivals` | `{ "<other id>": [lines] }` shown when facing that fighter. |

Keep every string within the [content rules](#8-content-rules-for-the-parody).

### 3.2a ROSTER field reference (look fields)

One line per look field. "Re-run" lists what must be run after changing it (see the
[full rebuild order](#full-rebuild-order-for-one-fighter) below); `roster` is
`build_showdown_roster.gd -- <id>`, `outfits` is `build_outfits.gd -- <id>`.

| Field | Type, units, range | Re-run |
|---|---|---|
| `skin` | `StringName` key of `SKINS` | roster (and aged skins if `age` is set) |
| `age` | Years (int, about 25-85). Lines start at 35 and reach full strength at 82; age spots from about 70. Also adds jowl sag through `FaceSculpt` (`face_shape["age"]`, jowls from 40) | `build_aged_skins.gd`, `build_aged_skins.py <id>`, `--import`, roster, outfits (the sag is baked into the body) |
| `face` | Dictionary of `FaceSculpt` params (table below), metres or factors | outfits, then roster |
| `face_rest` | `{blend shape: 0..1}` | roster |
| `eyes` | Iris name: `Brown`, `Blue`, `Green`, `Grey`, `DarkBrown` | roster |
| `brows` | `Vector3` scale (x length, y thickness, z depth), keep >= 0.7 | roster |
| `hair` | Array of hair piece names from `assets/characters/hair/` | roster |
| `hair_volume` | `[scale, offset]`: `Vector3` scale (x width, y height, z depth; 1 = as modelled) and `Vector3` offset in metres in head space (+Y up, +Z forward, applied after the scale). Becomes `CharacterData.hair_scale` / `hair_offset` and scales the real hair mesh (`FighterModel._rescale_skinned`). Typical: `[Vector3(1.18, 1.45, 1.22), Vector3(0, 0.012, 0.008)]` | roster |
| `scale` | Overall height factor (`model_scale`, about 0.9-1.1) | roster |
| `shape` | Per-bone flesh scale or `[scale, offset]` (see below) | roster |
| `posture` | `{bone: Vector3(x, y, z)}` rotation in **degrees** added on top of every animation, in bone space: X bends forward (+) or leans back (-), Y twists, Z tilts sideways. Bone names without `_l`/`_r` apply to both sides, mirrored for `_r` (Y and Z flip). Applied by `PostureModifier`; visual only, hitboxes and the simulation never see it. Typical: 3-15 degrees, e.g. `{spine_03 = Vector3(-6, 0, 0), Head = Vector3(-6, 0, 0)}` for a chest-out lean back | roster |
| `accessories` | Array of `&"glasses"`, `&"curls"`, `&"tousled"`, `&"swoop"` | roster |
| `prints` | `{slot index: name}`, e.g. `{0: "tee"}`. Slot index = the outfit colour slot (0 = main). Becomes `CharacterData.outfit_textures` from `assets/characters/prints/T_<id>_<name>.png`; replaces that slot's colour and weave (not used in mirror matches). Needs `PRINTS` in `tools/build_prints.py` | `build_prints.py`, `--import`, roster (`build_outfits.gd` only if the outfit spec changed) |

**Aged skins (`age`).** A two-step pass paints age lines into a copy of the fighter's skin:

1. `build_aged_skins.gd` exports the face geometry, landmarks and every roster fighter's
   age and skin to `assets/characters/aged/face_uv.json`.
2. `build_aged_skins.py` (Pillow and numpy) draws the lines and writes
   `assets/characters/aged/T_<id>_skin.png`. Pass ids to limit it.

The roster builder uses that file as `body_albedo` (and as the mirror-match skin) when it
exists. Each new PNG is imported by `--import`, and its `.import` must use VRAM compression
(see the print note below).

**Prints.** `tools/build_prints.py` reads the chest vertices from `face_uv.json` (so run
`build_aged_skins.gd` once first), draws each design in its `PRINTS` entry
(`id: (name, base colour, design function, centre in metres)`) and writes
`assets/characters/prints/T_<id>_<name>.png`. Designs must be original parody artwork: no
real logos, trademarks or brand marks. A new print `.png` imports lossless by default, and
`tests/sim_test.gd` ("Download size: no 3D texture is imported lossless") then fails. Copy
the `.import` pattern of `assets/characters/aged/T_donald_skin.png.import` next to the
print (same `compress/mode=1`, `compress/high_quality=false`, `mipmaps/generate=true`,
`detect_3d/compress_to=1`; change `source_file`, and drop the `uid` and `path`/`dest_files`
lines so Godot regenerates them on the next import):

```bash
cp assets/characters/aged/T_donald_skin.png.import assets/characters/prints/T_<id>_<name>.png.import
```

Then edit `source_file` in the copy and run `godot --headless --path . --import`.

### Body build, hair pieces and glasses

Three optional `ROSTER` fields (stored in the "Build" export group of `CharacterData` as
`model_scale`, `body_shape`, `accessories`, plus `accessory_color`) change a fighter's
silhouette without touching moves:

- `scale`: overall height (`model_scale`).
- `shape`: per-bone flesh scaling applied to the skin bind poses (`FighterModel._reshape`).
  It is visual only; bones, animations and hitboxes are unchanged. Keys are bone names
  without `_l`/`_r` (`pelvis`, `spine_01`, `spine_02`, `spine_03`, `neck_01`, `Head`,
  `clavicle`, `upperarm`, `lowerarm`, `hand`, `thigh`, `calf`, `foot`). A value is either a
  `Vector3` scale in bone space (Y along the bone, X width, Z depth/front) or
  `[scale, offset]`, where a positive Z offset pushes the flesh forward (a belly). Typical
  ranges: 0.8-0.95 for slim, 1.1-1.5 for heavy. Donald's belly is a good example: e.g.
  `spine_01 = [Vector3(1.55, 1, 1.85), Vector3(0, 0, 0.06)]` (wider, deeper, pushed
  forward); see his entry in `ROSTER` for the full set.
- `accessories`: array of `&"glasses"` (frame colour comes from `accessory_color`),
  `&"curls"`, `&"tousled"` or `&"swoop"`. They are built from simple meshes
  (`FighterModel._add_accessories` / `_piece`) on a `BoneAttachment3D` on the `Head`,
  placed relative to the eyes. `&"receding"` exists but is experimental. To add a new
  accessory, add a `match` branch in `FighterModel._add_accessories`.

After changing any of these, re-run `build_showdown_roster.gd -- <id>` and check the result
with the model sheet, which writes `docs/screenshots/roster.jpg` (front, side and head
close-up per fighter; ids after `--` are optional):

```bash
xvfb-run -a -s "-screen 0 1920x1080x24" godot --rendering-driver opengl3 --path . -s res://tools/render_model_sheet.gd -- <id>
```

### Face, eyes, brows and skin

Four optional `ROSTER` fields give each fighter a recognisable face on the shared base head
(`CharacterData.face_shape`, `face_rest`, `eye_texture`, `brow_scale`).

**`face`** is a dictionary of structure parameters, applied by `FaceSculpt.apply`
(`tools/face_sculpt.gd`) to the head vertices. It is **baked into the generated body** by
`tools/build_outfits.gd` (`_build` calls `FaceSculpt.apply` before the expression blend
shapes are made, so blinking and the mouth still fit). Changing `face` therefore needs
`build_outfits.gd -- <id>` to be re-run, not just the roster builder. All keys are optional;
0 / 1 means "as modelled":

| Key | Meaning (typical range) |
|---|---|
| `jaw` | Width of lower face and jaw, factor (0.93 narrow to 1.08 broad) |
| `chin` | Chin length, m (+ longer, - shorter/rounder; about +-0.004) |
| `chin_forward` | Chin projection, m (about +-0.004) |
| `cheekbones` | Cheekbone prominence, m outward (0 to 0.004) |
| `fullness` | Fuller (+) or hollower (-) cheeks and jowls, m (about +-0.004) |
| `nose_width` | Nose width, factor (0.9 to 1.12) |
| `nose_length` | Nose length, m (+ longer, tip lower; about +-0.004) |
| `nose_bridge` | Bridge height between the eyes, m (- flatter; about +-0.003) |
| `brow` | Brow ridge projection, m (+ heavier; 0 to 0.004) |
| `eye_fold` | 0..1: fuller upper lid with a softer fold, eye opening slightly narrower |
| `eye_tilt` | m, raises (+) the outer eye corners (about +-0.002) |
| `eye_open` | m, raises (+, rounder, wider) or lowers (-, hooded) the upper lid rim (about +-0.002) |
| `face_length` | Length of the face below the eyes, factor (0.95 to 1.06) |
| `lips` | Fuller, more forward lips, m (- thinner; about +-0.003) |
| `mouth_width` | Mouth width, factor (0.9 to 1.1) |
| `jowls` | Heavy jowls: flesh along the jaw line pushed out and down, m (0 to 0.006) |
| `double_chin` | A full double chin under the jaw, m (0 to 0.006) |
| `pout` | A pushed-out, pursed lower lip, m (0 to 0.004) |
| `chin_round` | Rounds off the jaw corners (pulled in at the angle of the jaw), m; a softer, rounder face (0 to 0.004) |
| `age` | Years. Normally set through the roster `age` field, not here; adds sagging jowls (from about 40), puffier lower lids and deeper smile lines |

Style guideline (from `FaceSculpt`): keep changes subtle, millimetre-scale and away from the
eyeballs and skull, so the shared brows, eyes and hair still sit right. Aim for recognisable
public-persona traits (a narrow jaw, heavy brows, a broad smile), never ethnic caricature.

**`face_rest`** is a resting expression: weights (0..1) for the `FighterModel.FACE_SHAPES`
blend shapes `blink`, `squint`, `brow_down`, `brow_up`, `jaw_open`, `smile` and `grimace`.
They are added to every expression (clamped to 1), e.g. `{brow_up = 0.55, smile = 0.2}` for a
perpetually eager look. It is plain data, so only the roster builder needs a re-run.

**`eyes`** is the iris texture name: `"Brown"`, `"Blue"`, `"Green"`, `"Grey"` or `"DarkBrown"`,
loaded from `assets/characters/base/T_Eye_<name>.png` (`FighterModel._customize_materials`).
Omit it to keep the default eye.

**`brows`** is a `Vector3` `brow_scale` applied to the eyebrow mesh about its own middle
(`FighterModel._shape_brows`): x length, y thickness/arch, z depth. `y < 1` makes brows
slimmer and straighter, `y > 1` heavier. Keep every component at about 0.7 or more, or the
brows sink into the skin.

**`skin`** picks a body texture from `SKINS`: `light`, `light_alt`, `medium`, `brown`, `tan`,
`pale`, `warm`. Add a texture and a `SKINS` entry for a new tone.

Order of work after editing these fields:

1. Edit the `ROSTER` entry.
2. `build_showdown_roster.gd -- <id>` (writes `face_rest`, `eyes`, `brows`, `skin`).
3. `build_outfits.gd -- <id>` (bakes `face` into the body).
4. Render `render_portraits.gd`, `render_cutins.gd` and `render_model_sheet.gd -- <id>` and
   check the head close-ups.
5. `godot --headless --path . --import`.
6. `build_showdown_roster.gd -- <id>` again, so the portrait links up.


3. Prints (only if the fighter has `prints`; add the `.import` copy described above):

```bash

```

5. Build the character data:


6. Bake the outfit and face (`face`, `age` sag):

```bash
godot --headless --path . -s res://tools/build_outfits.gd -- <id>
```

7. Render the model sheet, then the portrait and cut-in, and check them:

```bash
xvfb-run -a -s "-screen 0 1920x1080x24" godot --rendering-driver opengl3 --path . -s res://tools/render_model_sheet.gd -- <id>
```

```bash
xvfb-run -a -s "-screen 0 1920x1080x24" godot --rendering-driver opengl3 --path . -s res://tools/render_portraits.gd -- <id>
```

```bash

```

8. Import the renders, then rebuild once more so the new portrait is linked:

```bash
godot --headless --path . --import
```

```bash

```

### 3.3 Pipeline, in this order

1. Build the character and its moves (no portrait yet; that is fine):

```bash
godot --headless --path . -s res://tools/build_showdown_roster.gd -- <id>
```

2. Add an outfit spec in `_showdown_specs()` of `tools/build_outfits.gd`, keyed by the id.
   Use a helper: `_suit_spec`, `_sweater_spec`, `_tee_spec`, `_leather_jacket_spec`,
   `_hoodie_spec`, `_cardigan_spec` or `_bodysuit_spec` (read the doc comment above each
   for its colour slots; copy a neighbour, e.g. `"donald"` for a suit). Outfits have a 5th
   slot, `Slot.DETAIL`, made of metal hardware (fabric `&"metal"`): zips, buttons and
   similar; `_leather_jacket_spec` and `_suit_spec` already use it for zips, collar, lapels
   and buttons. This step also bakes the fighter's `face` parameters into the body. Then
   generate it:

```bash
godot --headless --path . -s res://tools/build_outfits.gd -- <id>
```

3. Add an expression to `FACES` in `tools/render_portraits.gd` (blend shape weights
   `brow_up`, `brow_down`, `smile`, `squint`, `grimace`; `{}` keeps the neutral face).
4. Render the portrait and the super cut-in (windowed or Xvfb, see [section 2](#tools-that-render-images)):

```bash
xvfb-run -a -s "-screen 0 1920x1080x24" godot --rendering-driver opengl3 --path . -s res://tools/render_portraits.gd -- <id>
```

```bash
xvfb-run -a -s "-screen 0 1920x1080x24" godot --rendering-driver opengl3 --path . -s res://tools/render_cutins.gd -- <id>
```

5. Import the new PNGs:

```bash
godot --headless --path . --import
```

6. Re-run the roster builder so the character links its portrait (it keeps the generated
   outfit data from the previous build):

```bash
godot --headless --path . -s res://tools/build_showdown_roster.gd -- <id>
```

7. Update `tests/sim_test.gd`: add the id to `SHOWDOWN_IDS` (in select order), and adjust
   the checks in `showdown_tests()` that hard-code the count or order (the
   "all 12 fighters load" check, arcade ladder size via `gs.roster.size()`, rival lines).
8. Run the tests:

```bash
godot --headless --path . -s res://tests/sim_test.gd
```

To **change** an existing fighter, edit the same `ROSTER` entry and re-run step 1
(and steps 4-6 if the look changed). Regenerating overwrites `data/characters/<id>.tres`
and `data/moves/<id>/*.tres`.

## 4. Tweak moves and balance

Do **not** hand-edit `data/moves/<id>/*.tres` or `data/characters/<id>.tres`: re-running
`build_showdown_roster.gd` rewrites them. Instead:

- **Per fighter:** change `damage` (multiplier) or `stats` in that fighter's `ROSTER` entry.
- **Per kit** (affects every fighter on it, and the original cast): frame data and stats
  are generated by `tools/build_movesets.gd` into `data/kits/`; change it there, re-run it,
  then re-run the roster builder so copies in `data/moves/<id>/` update. Update the numbers
  in `docs/characters/<kit>.md` too.

Field reference for a move is the `@export` list in `scripts/fighter/move_data.gd`:
`input` notation (`"LP"`, `"2LK"`, `"236P"`, `"236236P"` for supers, `"~"` prefix for
follow-ups), `animation`, `startup`/`active`/`recovery` (60 Hz ticks), `damage`,
`hit_level` (`HIGH`/`MID`/`LOW`/`OVERHEAD`), `hitstun`, `blockstun`, `hitstop`,
`knockback`, `launches`, `knockdown`, `lunge`, `chip_damage`, and more.

### Balance simulator

`tools/balance_sim.gd` plays CPU-vs-CPU matches for every pairing (both sides) and prints
a win-rate matrix, per-fighter stats and a frame-data audit. Arguments after `--`:
`[matches] [difficulty 0-2] [id|all] [stage]`. Check one fighter after a change:

```bash
godot --headless --path . -s res://tools/balance_sim.gd -- 6 2 tesla
```

Full roster (slow):

```bash
godot --headless --path . -s res://tools/balance_sim.gd -- 6 2 all
```

CPU personalities shape the results, so treat outliers as hints, not verdicts. Raw results
are written to `user://balance_results.json`.

### Giving a fighter its own moveset

A roster fighter can play differently from its kit. Its overrides live in `MOVESETS` in
`tools/showdown_movesets.gd`, keyed by fighter id. The `sundar` entry is a full example:
it removes two kit moves, tweaks one, adds three and sets its own trials. Do not edit
`data/moves/<id>/` by hand. The roster builder rewrites it.

Keys (all optional):

- `remove`: kit move files to drop, e.g. `remove = ["dragon_barrage", "dragon_finish"]`.
  Drop a super's follow-ups with it.
- `tweak`: `{move_file: {field: value}}` sets fields on a kept move, e.g.
  `tweak = {ki_blast = {projectile_count = 3}}`. Values are final: damage is not scaled.
- `add`: `{new_file: {from = "<moves folder>/<file>", set = {field: value}}}` clones a move
  from `data/moves/`, then applies `set`, e.g.
  `add = {algorithm_update = {from = "kenji/ki_blast", set = {name = "Algorithm Update", input = "214K", teleport = 1.0}}}`.
  `damage` and `chip_damage` are scaled by the ROSTER `damage` unless `set` gives them.
  Give it a `name` and an `input`.
- `stats`: `{CharacterData field: value}`, e.g. `stats = {max_health = 1020}`. Applied
  after the ROSTER `stats`.

Order of application (`tools/build_showdown_roster.gd`):

1. The ROSTER `stats`, then the moveset's `stats`.
2. The kit's moves are copied into `data/moves/<id>/`, minus the `remove` files. ROSTER
   `moves` names are applied and damage is scaled by the ROSTER `damage`.
3. `tweak` on the kept moves. Keys are the kit's file names, not the new names. A tweak of
   a removed or unknown move stops the build.
4. `add`: each clone is built from its source, then `set` is applied.
5. Any `.tres` left in `data/moves/<id>/` that is no longer built is deleted.

Rebuild one fighter (leave out the id to rebuild all of them):

```bash
godot --headless --path . -s res://tools/build_showdown_roster.gd -- sundar
```

Check its balance:

```bash
godot --headless --path . -s res://tools/balance_sim.gd -- 4 2 sundar
```

`balance_sim.gd` takes matches, difficulty (0-2) and the fighter id, as in section 4.

CPU style and showcase are looked up by fighter id too. `SHOWDOWN_PERSONALITIES` in
`scripts/ai/ai_controller.gd` and `ROUTINES` in `scripts/ui/fighter_showcase.gd` are keyed
by id. `CharacterData.lookup()` (`scripts/character_data.gd`) returns the entry for the
fighter's id. If there is none, it returns the entry for the kit (`kit_id()`). The CPU then
falls back to `PERSONALITIES` and `DEFAULT_PERSONALITY`. The showcase falls back to a plain
idle loop. So a fighter with no entry of its own plays its kit's style and routine.

### New MoveData fields

Set these in an `add` `set` or a `tweak` in `tools/showdown_movesets.gd`, or in a kit's move
(`data/kits/`, through `tools/build_movesets.gd`).

| Field | What it does | Example |
|---|---|---|
| `projectile_count` | Shots per move. With `projectile_interval` 0 they leave together, stacked by `projectile_spread`. | `3` |
| `projectile_interval` | Ticks between shots, while the move is still active. 0 = all at once. | `12` |
| `projectile_spread` | Metres between shots: vertical for hand shots, along the fight axis for sky shots. | `0.35` |
| `projectile_origin` | `&""` = from the hand, flying forward. `&"sky"` = falls from above the opponent (`projectile_speed` is the fall speed). `&"around"` = comes in from a half circle around the opponent. | `&"sky"` |
| `projectile_sky_offset` | Shifts sky shots along the fight axis, in metres. | `1.5` |
| `barrier` | The shot is a wall: no damage, destroys opponent projectiles it touches, pushes the opponent out. Moves at `projectile_speed` (0 = stays put) for `projectile_lifetime` ticks. One at a time. | `true` |
| `reflect_projectiles` | During startup and active frames, opponent projectiles that touch the fighter are sent back at the opponent. | `true` |
| `teleport` | On the first active frame, the fighter moves this many metres past the opponent. Negative = that far back from where it stands. | `1.0` |
| `drain_meter` | Super meter taken from the opponent and given to the attacker when the move hits or its grab connects. | `10` |
| `projectile_look` | Cosmetic shot model: `&""` = orb, `&"search_bar"`, `&"gpu"` (`scripts/supers/projectile_looks.gd`). | `&"gpu"` |
| `super_fx` | Cosmetic SuperFX show played when the super starts (`scripts/supers/`). | `&"search_result"` |

`fires_projectile()` is a method, not a field. It returns true when the move has
`projectile_speed` above 0 or `barrier` set. Use it instead of checking those two by hand.

## 5. Power-move voices

Fighters without their own clips fall back to the shared voice in `voice` (special and KO
only). A **super** never falls back: its shout names the move, so it needs its own clip or
it is silent.

1. Record or generate a short clip of the fighter's super line.
2. Save it as `assets/audio/voice/fighters/<id>_super_1.ogg` (`.wav` and `.mp3` also work;
   `SHOUT_EXTENSIONS` in `scripts/autoload/audio.gd`). Add `_2` to `_8` for variety:
   `Audio.shout()` picks a random take (`_shout_takes()` loads `<id>_<kind>_1..8`).
3. Kinds are `special`, `super` and `ko`: `<id>_special_N.ogg`, `<id>_super_N.ogg`,
   `<id>_ko_N.ogg`.
4. Import:

```bash
godot --headless --path . --import
```

5. Regenerate the mouth-movement envelopes. `FighterModel.speak()` opens the jaw from
   `assets/audio/voice/fighters/mouth.json` (needs `ffmpeg` on `PATH` and `numpy`):

```bash
python3 tools/build_voice_envelopes.py
```

Voices must be original or properly licensed; list any third-party source in
`assets/CREDITS.md`. Never clone a real person's voice.

## 6. Stages

`GameState.STAGES` (3 entries: Server Farm, Mensa, Senate Hearing Room) is the AI Showdown
list; `GameState.ENGINE_STAGES` (8 original stages) is only used by the engine tests via
`use_engine_content()`. Each entry is `{path, name, thumb, blurb}`.

The three Showdown stages are **inherited scenes** of original stages. Each contains a
`Retheme` node running `scripts/stages/stage_retheme.gd` (`class_name StageRetheme`) that
removes props that don't fit and builds new ones from primitives at load time. Props are
**cosmetic only**: no collision and nothing the simulation reads, so a retheme can never
change gameplay. Inherited stage bounds, walls and camera come from the base scene.

| Stage | Scene | Base scene | `Look` |
|---|---|---|---|
| Server Farm | `scenes/stages/server_farm.tscn` | `rooftop.tscn` | `SERVER_FARM` |
| Mensa | `scenes/stages/mensa.tscn` | `dojo.tscn` | `MENSA` |
| Senate Hearing Room | `scenes/stages/senate.tscn` | `ring.tscn` | `SENATE` |
| GPU Foundry | `scenes/stages/foundry.tscn` | `market.tscn` | `FOUNDRY` |

Helpers in `stage_retheme.gd`: `_mat`, `_glow`, `_box`, `_cylinder`, `_instance`, `_label`
(`Label3D` signs), `_board`, `_light`, `_person` (a seated spectator), `_bunny_person`
(a cleanroom technician), `_checker`, `_relabel` (rename text on an inherited sign) and
`_remove` (delete a base prop by node name; open the base scene in the editor to find names).

### Add a stage

1. In `scripts/stages/stage_retheme.gd`, add a value to `enum Look` and a branch in
   `_ready()`'s `match look:` calling a new `_build_<name>()`. Model it on `_build_mensa()`
   or `_build_senate()`: `_remove`/`_relabel` the base props, then add floor, props and
   lights.
2. Create `scenes/stages/<name>.tscn` as an inherited scene of the base stage you want
   (copy `scenes/stages/mensa.tscn`: change the base `ext_resource`, the root node name
   and set `look = <index of your enum value>`).
3. Add a `const <NAME>_STAGE := "res://scenes/stages/<name>.tscn"` and an entry to
   `GameState.STAGES` in `scripts/autoload/game_state.gd` (`path`, `name`, `thumb`
   `res://assets/ui/stages/<name>.png`, `blurb`).
4. Import so the scene registers, then render the thumbnail (use the scene file name
   without extension; thumbnails are 640x360):

```bash
godot --headless --path . --import
```

```bash
xvfb-run -a -s "-screen 0 1920x1080x24" godot --rendering-driver opengl3 --path . -s res://tools/render_stage_thumbs.gd -- <name>
```

5. Update `tests/sim_test.gd`: the "Showdown: four stages with thumbnails" check expects
   `gs.STAGES.size() == 4`; raise it with every stage you add. The loop below it checks
   every stage has a `Retheme` node with at least 10 children, so make sure yours builds
   enough props.
6. Optionally add a shot in `FIGHTS` of `tools/render_screenshots.gd`.
7. Run the tests.

## 8. Content rules for the parody

AI Showdown satirises **public personas and publicly stated ideas**, in the spirit of
political cartoons. Every fighter, move name, line and stage must follow these:

- Satire of public personas and ideas only: what someone is known for saying or doing
  publicly, exaggerated for comedy.
- Made-up names (parody spellings such as "Ram Altman"), never the real name.
- No real logos, trademarks, photos or likenesses. Fighters use the generic low-poly body,
  a hair colour and generic clothes.
- No humiliating, degrading, sexual or ethnic-caricature content. No slurs, no jokes
  about appearance, health, family, religion or ethnicity. Punch up at ideas, hype and
  institutions, not at who someone is.
- No claims presented as fact about real people's private lives, crimes or conduct.
- Keep the disclaimer on the title screen, main menu and splash.

If in doubt, leave it out; maintainers may ask for lines to be changed or removed.
